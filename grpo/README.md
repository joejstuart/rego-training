# GRPO Training — Rego Expert Reasoning Model

Stage 2 of the training pipeline. After SFT teaches the model Rego syntax and
policy patterns, GRPO (Group Relative Policy Optimization) teaches it to
**reason** through ambiguous prompts, diagnose errors, and produce
structurally correct output.

## Architecture

```
┌──────────────────────────────┐
│  SFT Model (sft/train.py)   │  Rego fluency, deny patterns, schema grounding
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│  GRPO Dataset                │  609 prompts with ground-truth tests
│  (build_dataset.py)          │  standard + error-fix + custom-value variants
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│  GRPO Training (train.py)    │  GRPOTrainer from TRL
│                              │  5 reward functions scored by OPA/Regal
│                              │  Per-step JSONL logging
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│  rego-expert-grpo-8b        │  LoRA adapter (or merged model)
│  output/                     │  + step_log.jsonl for analysis
└──────────────────────────────┘
```

## Reward Functions

Five stacked reward signals (defined in `rewards.py`):

| # | Function | Score Range | What It Checks |
|---|----------|-------------|----------------|
| 1 | `reward_format` | +5.0 / −7.0 | Structural compliance: `<think>` block, `package`, `import rego.v1`, `deny contains msg if` |
| 2 | `reward_opa_parse` | +2.0 / −2.0 | Syntactic validity via `opa check` |
| 3 | `reward_opa_test` | +5.0 / −4.0 | Functional correctness via `opa test` (uses ground-truth tests) |
| 4 | `reward_schema_paths` | +3.0 / −3.0 | Schema grounding — all `input.*` paths match the SLSA attestation catalog |
| 5 | `reward_regal_lint` | +2.0 / −2.0 | Idiomatic Rego style via `regal lint` (disabled rules: `opa-fmt`, `directory-package-mismatch`, `external-reference`, `leaked-internal-reference`, `rule-length`, `file-length`) |

**Total signal range:** +15.0 (perfect) to −17.0 (worst).

## Dataset

The GRPO dataset (`output/grpo_prompts.jsonl`) contains **609 prompts** across
12 variant types:

| Category | Variants | Count | Purpose |
|----------|----------|-------|---------|
| **Standard** | canonical, terse, vague, poor_grammar | 240 | Robust instruction following |
| **Ambiguous** | ambiguous | 35 | Schema resolution under vagueness |
| **Error Fix** | error_fix_style, error_fix_syntax, error_fix_parse, error_fix_logic, error_fix_unsafe_var | 276 | Diagnose and fix broken Rego code |
| **Custom Value** | custom_value_value_swap, custom_value_operator_flip | 58 | Generalize beyond memorized literals |

Each record includes:
- `prompt`: `[system, user]` message list
- `test_code`: ground-truth Rego test for `reward_opa_test`
- `rule_code`: reference rule (not shown to model)
- `package_name`, `task_id`, `variant`: metadata

### Building the Dataset

```bash
# From the project root:
python -m grpo.build_dataset

# Inspect:
wc -l grpo/output/grpo_prompts.jsonl
head -1 grpo/output/grpo_prompts.jsonl | python -m json.tool
```

The builder reads Phase 1 instructions, Phase 3 rules/tests, and Phase 4
ambiguous prompts. Error-fix variants are generated by programmatically
corrupting ground-truth rules and capturing actual `opa check` / `opa test` /
`regal lint` error output.

## Training

```bash
# Default (with Unsloth + vLLM for fast generation)
python -m grpo.train

# Without Unsloth (slower, more VRAM, but avoids version conflicts)
python -m grpo.train --no-unsloth

# Point to a specific SFT checkpoint
python -m grpo.train --sft-model ./sft/output/rego-expert-8b

# Adjust training
python -m grpo.train --max-steps 200 --num-generations 8 --batch-size 8

# Dry run (loads dataset, prints config, no training)
python -m grpo.train --dry-run

# Optimal command (Unsloth + vLLM — fastest)
python -m grpo.train \
    --sft-model sft/output/rego-expert-8b \
    --num-generations 4 \
    --batch-size 4 \
    --grad-accum 2 \
    --max-steps 600 \
    --lr 5e-6 \
    --lora-rank 32 \
    --log-every 5

# Same but without Unsloth (if Unsloth/vLLM not installed)
python -m grpo.train \
    --sft-model sft/output/rego-expert-8b \
    --no-unsloth \
    --num-generations 4 \
    --batch-size 4 \
    --grad-accum 2 \
    --max-steps 600 \
    --lr 5e-6 \
    --lora-rank 32 \
    --log-every 5
```

### Key Arguments

| Argument | Default | Description |
|----------|---------|-------------|
| `--sft-model` | `sft/output/rego-expert-8b` | Path to SFT-trained model (LoRA or merged) |
| `--output-dir` | `grpo/output/rego-expert-grpo-8b` | Output directory for GRPO checkpoints |
| `--max-steps` | `600` | Maximum GRPO training steps |
| `--num-generations` | `4` | Completions per prompt (for group comparison) |
| `--batch-size` | `4` | Per-device batch size (must be ≥ `num-generations`) |
| `--lora-rank` | `32` | LoRA rank for GRPO adapter |
| `--lr` | `5e-6` | Learning rate |
| `--log-every` | `5` | Console summary frequency (steps) |
| `--no-unsloth` | off | Skip Unsloth, use standard HF/TRL |
| `--dry-run` | off | Print config without training |

### Training Hyperparameters

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| KL penalty (β) | 0.10 | Moderate — allows improvement while preventing regression on under-seen prompts |
| Temperature | 0.7 | Encourages exploration while keeping outputs coherent |
| Max completion length | 1028 | Sufficient for rule + `<think>` trace |
| Save steps | every 50 | Periodic checkpoints |

## Logging and Analysis

Training produces a `step_log.jsonl` file with per-step detail:

```json
{
  "step": 42,
  "task_id": "task_status_check",
  "variant": "terse",
  "prompt": "deny if any task status != Succeeded",
  "completions": [
    {"code": "...", "think": "...", "rewards": {"reward_format": 3.0, ...}, "total_reward": 12.0}
  ],
  "reward_mean": 10.5,
  "reward_std": 2.1,
  "had_learning_signal": true
}
```

### Quick analysis:

```bash
# Pandas analysis
python -c "
import json, pandas as pd
rows = [json.loads(l) for l in open('grpo/output/rego-expert-grpo-8b/step_log.jsonl')]
df = pd.json_normalize(rows)
print(df[['step','task_id','variant','reward_mean','had_learning_signal']].to_string())
"
```

## Design Decisions

### Why GRPO instead of PPO?

GRPO compares multiple completions per prompt, using the group's relative
performance as the reward baseline. This eliminates the need for a separate
reward model (as in PPO) and works well with deterministic reward functions
like OPA evaluation.

### Why five reward functions?

Each function targets a different failure mode:
- **format**: prevents structural regressions (missing `contains`, wrong pattern)
- **opa_parse**: catches syntax errors early
- **opa_test**: the strongest signal — does the rule actually work?
- **schema_paths**: prevents hallucinated field references
- **regal_lint**: encourages idiomatic Rego style

### Why error-fix variants?

Training on error-fix prompts teaches the model to:
1. Read and interpret OPA/Regal error messages
2. Diagnose the root cause in the code
3. Generate a corrected version

This is critical for real-world usage where users may paste broken rules.

### Why β = 0.10 for the KL penalty?

The SFT model already gets many prompts right — GRPO should improve on
ambiguous cases without regressing on what SFT already knew. An earlier
value of 0.04 was too permissive: the model drifted and forgot correct
SFT behaviour on prompts it didn't encounter often during GRPO training.
0.10 keeps the model anchored to SFT while still allowing meaningful
improvement where the reward signal is strong.
